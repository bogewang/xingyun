# 销售出库买菜汇总2设计

## 目标

在 `/sale/out` 页面新增“买菜汇总2”导出入口。该功能按用户勾选的销售出库单生成按客户动态展开的汇总 Excel，同时保留现有“买菜汇总”的按钮、接口、数据格式和实现不变。

## 范围

- 新增前端按钮、导出 API、Controller 路由和 Service 导出方法。
- 仅接收勾选单据的 `idList`；未勾选时前端提示，后端仍执行同样的业务校验。
- 复用既有的单据查询、明细查询、商品/分类/单位批量加载和按“日期 + 商品”聚合逻辑。
- 不修改既有 `marketBuySummary` 方法及其 `/export/marketBuySummary` 路由。

## 导出格式

表头使用稳定的 `LinkedHashMap`，顺序固定为：

1. 日期
2. 分类
3. 商品名称
4. 单位
5. 本次勾选单据中每位客户的一列
6. 总计

客户列按勾选单据查询结果的首次出现顺序生成。列标题优先取客户 `nickName`；`nickName` 为 `null`、空字符串或全空白时回退到客户 `name`。列数据键使用客户 ID，避免客户简称或名称重复时覆盖列数据。

每行表示同一订单日期和同一商品的汇总：

- 日期按既有格式 `yyyy/M/d` 输出。
- 分类、商品名称与单位来自商品基础资料。
- 某客户列展示该客户在该日期、商品下的数量；存在备注时追加去重且保持出现顺序的备注文本，例如 `0.1（2条大）`。
- 不存在该客户的商品数量时该单元格为空。
- 总计为该行所有客户数量之和，仅展示数值，不拼接单位。
- 排序保持既有规则：分类、商品名称、日期升序。

## 架构与接口

- 前端 `sheet-list.vue` 新增“买菜汇总2”按钮和独立点击方法，继续使用勾选记录构造 `idList`。
- 前端 API 新增 `exportMarketBuySummary2`，以 JSON POST 请求 `/sale/out/sheet/export/marketBuySummary2` 并下载 Blob。
- Controller 新增独立导出方法，权限与原功能一致：`sale:out:query`。
- Service 接口和实现新增 `marketBuySummary2(QuerySaleOutSheetVo vo)`。该方法调用独立的表头和行数据构建方法，并复用无模型 Excel 导出。

## 错误处理

- 空 `idList` 抛出 `DefaultClientException("请选择要汇总的销售出库单！")`。
- Controller 捕获非业务异常，记录错误日志并转换为 `DefaultClientException`，遵循当前导出接口模式。
- 无匹配单据或无明细时仍导出只有表头的空 Excel。

## 测试

- 前端单元测试验证“买菜汇总2”请求参数仅包含有效单据 ID。
- 后端单元测试验证动态表头中“日期”首列、客户简称优先/名称回退、客户列顺序及总计列位置。
- 后端单元测试验证客户单元格数量与备注格式，以及空 ID 列表的业务异常。

## 不在范围内

- 不修改原“买菜汇总”的表头、动态列策略、接口地址或导出文件内容。
- 不新增权限编码、数据库表、配置项或事务。
