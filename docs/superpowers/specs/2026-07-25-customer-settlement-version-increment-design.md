# 客户结算源单状态回写版本递增设计

## 背景

客户直接结算通过销售出库单和销售退货单的结算状态回写维护源单状态。旧客户结算入口也调用相同的状态回写，但该回写未递增源单版本，导致基于旧版本发起的直接结算请求可能绕过并发防线。

## 方案

在销售出库单与销售退货单 Service 的 `setPartSettle`、`setSettled` 状态更新中，使用既有状态条件更新结算状态，并同时将 `version` 递增 1。所有结算入口复用这些 Service 方法，因此无需在各旧入口重复维护版本。

更新仍以受影响行数为 1 作为成功条件；返回 0 时调用方继续按现有逻辑抛出 `DefaultClientException` 并回滚事务。

## 范围

- 仅修改销售出库单和销售退货单的结算状态回写。
- 增加回归测试，验证部分结算和完全结算都会携带版本递增。
- 不修改客户结算工作台、结算单数据结构或旧流程的业务规则。

## 验收标准

1. 任一入口调用两类源单的结算状态回写时，更新语句同时设置 `version = version + 1`。
2. 原有状态更新条件保持不变。
3. 相关单元测试通过，且能证明更新包装器包含版本递增设置。
