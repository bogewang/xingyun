# 客户结算对账工作台设计

## 目标

将当前客户“直接结算”工作台调整为与供应商结算一致的两阶段流程：先确认对账，再确认结算。客户结算覆盖销售出库单和销售退货单，两类单据必须独立处理。

## 范围

- 客户工作台展示销售出库单和销售退货单，并显示对账、结算金额及状态。
- 恢复客户对账单和对账明细，作为可查询、可追溯的对账记录。
- 保留客户结算单和结算明细，作为可查询、可追溯的结算记录。
- 不恢复旧的客户对账独立增改审页面；对账由工作台直接确认。
- 不改动供应商结算功能，也不执行数据库迁移。

## 单据与状态

每次操作只允许勾选同一客户、同一业务类型的单据。销售出库单和销售退货单不可混选；销售退货的对账和结算金额均按正数输入，业务类型表达退款含义。

源单状态按如下路径流转：

```
待对账（7） --确认对账--> 待结算（0） --确认结算--> 部分结算（1）或已结算（3）
```

已结算单据不可再次对账或结算。待结算和部分结算单据不可再次对账。

## 金额规则

### 确认对账

对账总金额必须大于零且最多两位小数。以所选单据原金额合计为基数，计算：

```
对账差额 = 输入对账总金额 - 所选单据原金额合计
```

仅将“对账差额”平均分摊到各对账明细的差额（优惠）字段，保留两位小数，最后一条补足尾差；不得把输入的对账总金额再次分摊。每条对账后的金额等于原单金额加该条差额，且所有明细对账后金额之和严格等于输入总额。任何分摊结果为负数时拒绝并回滚。

### 确认结算

结算总金额必须大于零且最多两位小数。结算基数为各已对账单据的“已对账金额 - 已结算金额”之和，计算：

```
结算差额 = 输入结算总金额 - 所选单据当前未结算金额合计
```

仅将“结算差额”平均分摊到各结算明细的差额（优惠）字段，保留两位小数，最后一条补足尾差；不得把输入的结算总金额再次分摊。每条本次结算金额等于该条未结算金额加该条差额，所有结算明细合计严格等于输入总额，且不得使任一单据的累计结算额超过其已对账金额或变成负数。

## 后端

恢复 `CustomerSettleCheckSheet`、`CustomerSettleCheckSheetDetail` 及其 Mapper、Service、VO、BO、导出模型和最小查询接口。只提供工作台所需的直接确认对账、记录查询和导出能力，不恢复旧式独立增改审流程。

客户工作台批量读取销售出库单、销售退货单、客户对账明细和客户结算明细，补齐对账金额、对账时间、对账备注、结算金额、结算时间、状态等字段，避免循环查询数据库。

直接确认对账在 Service 事务中校验单据、客户、类型、状态和金额，创建已确认的客户对账单及明细，然后以状态及结算版本号乐观锁将源单更新为待结算。直接确认结算仅接受待结算或部分结算单据，在同一事务中创建结算单及明细，并以同样的乐观锁更新源单为部分结算或已结算。任一更新失败抛出 `DefaultClientException` 并整体回滚。

Controller 只进行参数校验与 `InvokeResult` 包装；业务校验和事务仅在 Service 中完成。

## 前端

客户工作台增加“确认对账”按钮和对账金额弹窗，并保留“确认结算”。按钮仅在相应状态下可用：待对账单据可对账，待结算或部分结算单据可结算。前端同样限制同一客户、同一业务类型，且禁止销售出库和销售退货混选。

表格展示对账金额、结算金额、对账/结算时间和备注，保留结算记录，并提供对账记录的查询或导出入口，保证业务可追溯。

## 测试与验收

- 后端：销售出库与销售退货分别覆盖全额/部分对账、全额/部分结算、差额分摊、尾差、负数分摊、跨客户混选、跨业务类型混选、重复对账、已结算拦截和乐观锁冲突。
- 前端：覆盖对账/结算按钮状态、同客户同类型勾选限制、对账/结算请求参数及金额提示。
- 构建：相关 Maven 测试和前端 Vitest、lint 通过。
