# 采购收货单已结算付款金额展示设计

## 目标

修正采购收货单列表中已结算单据的“本单已付”和“未付金额”展示，使结算款与单据付款金额共同反映实际付款进度。

## 数据与计算规则

结算模块的收货单扩展查询接口返回以下字段：

- `checkAmount`：单据对账金额。
- `settleAmount`：单据结算金额。

列表行的展示金额按以下规则计算：

- 当 `settleStatus = 3`（已结算）时：
  - 本单已付 = `settleAmount + paidAmount`
  - 未付金额 = `checkAmount - settleAmount - paidAmount`
- 其他结算状态继续使用接口原有的 `paidAmount` 和 `unpaidAmount`。

## 方案

- 结算模块已有 `ReceiveSheetSettleInfoBo`，其已聚合收货单与关联结算记录。将该模块已有的收货单扩展查询接口调整为分页响应，并保留 `checkAmount` 与 `settleAmount` 字段。
- 前端采购收货单列表改用该结算模块接口及对应 API 模型；不让 `xingyun-sc` 反向依赖 `xingyun-settle`，也不在前端发起第二次查询后合并数据。
- 前端合计行构建函数接收列表行字段；对已结算行按新公式计算并汇总，对其他状态保持现有值。
- 为前端纯函数增加已结算与非已结算的回归测试，保证单行展示与合计均遵循相同口径。

## 范围与约束

- 仅影响采购收货单列表及其合计行，不调整结算业务、单据持久化数据或其他页面。
- 结算状态使用既有枚举 `SETTLE_STATUS.SETTLED`，其编码为 `3`。
- 金额字段为空、非法或非有限时按既有前端安全数值规则视为 `0`。

## 验收标准

- 已结算单据的本单已付展示为结算金额与单据已付金额之和。
- 已结算单据的未付金额展示为对账金额减结算金额再减单据已付金额。
- 未结算、部分结算、待对账及无需结算单据维持原有展示口径。
- 合计行汇总上述展示后的金额，不再直接汇总原始字段。
