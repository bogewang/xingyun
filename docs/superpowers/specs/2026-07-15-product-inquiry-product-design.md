# 商品询价标识设计

## 背景与目标

商品管理新增“询价商品”字段，用于标识商品价格是否需要询价。字段在数据库中以 `1/0` 存储，并在商品新增、修改、查看、列表、Excel 导入及导出中完整呈现和维护。

## 数据模型与接口

1. 在租户库的 `base_data_product` 增加 `inquiry_product TINYINT(1) NOT NULL DEFAULT 0` 字段；已有商品因默认值均为非询价商品。
2. Java 实体、创建/修改请求以及商品查询列表、详情响应统一使用 `Boolean inquiryProduct`。MyBatis-Plus 将布尔值映射为数据库中的 `1/0`。
3. 新增商品未传该字段时按 `false` 保存；前端新增表单默认提交 `false`。
4. 修改商品由前端复选框提交明确的布尔值，并覆盖原值。

## 页面交互

1. 商品新增和修改页增加“询价商品”复选框；勾选表示“是”（`true`），未勾选表示“否”（`false`），默认不勾选。
2. 商品详情弹窗显示“询价商品”，将 `true/false` 显示为“是/否”。
3. 商品查询区域新增“询价商品”下拉筛选，提供“全部 / 是 / 否”三个选项，默认“全部”。
4. 商品列表增加“询价商品”列，展示值为“是/否”，随现有列配置参与展示。

## Excel 导入与导出

1. 商品导入模板和商品导出文件均增加“询价商品”列，值为“是”或“否”。
2. 导入时仅接受“是/否”；其他非空值报出含行号和字段名的受控业务异常。
3. 旧模板未包含该列或单元格为空时：
   - 新增商品按“否”（`false`）保存；
   - 匹配到已有商品并执行更新时保留数据库原值。
4. 导出将数据库中的 `true/false` 稳定转换为“是/否”，导出的文件可再次导入而不改变字段语义。

## 实现边界

1. 商品查询请求增加可空的 `inquiryProduct` 条件：未传时查询全部，传 `true` 或 `false` 时仅查询对应商品；查询响应也返回该字段，商品列表据此新增展示列。
2. 不修改采购、销售、库存等下游业务规则；“询价商品”仅作为商品基础资料标识。
3. 导入仍沿用现有批量新增、批量更新及同一 Service 事务，不在循环中新增数据库查询。

## 测试策略

1. 增加导入值转换的单元测试：识别“是/否”、拒绝非法值。
2. 验证导入空值的兼容规则：新增商品默认 `false`，更新商品保留原 `inquiryProduct`。
3. 验证创建请求的空值默认 `false`，以及修改请求可持久化 `true` 或 `false`。
4. 验证商品查询在 `inquiryProduct` 为空、`true`、`false` 时分别返回全部、询价、非询价商品。
5. 前端类型检查与 lint 验证新增字段、表单默认值、筛选条件及展示逻辑。
