# 报价单管理与销售定价设计

## 目标

在商品中心提供报价单管理。报价单为全租户通用的商品销售价格表，按闭区间定价周期生效。开启 `sale_out_price_use_unique_price` 后，销售出库单只能选择单据日期命中的已启用报价单内商品，并以报价单价格定价。

## 范围与约定

- 报价单不区分客户、仓库或销售人员。
- 每张报价单包含名称、开始日期、结束日期、状态和备注（不需要编号）；明细包含商品与销售单价。
- 定价周期按开始、结束日期均包含的闭区间计算。
- 任意两张未删除报价单的定价周期不得重叠，状态不影响该限制。
- 报价单已被销售明细引用时不能删除，可停用；停用不修改既有销售单。
- 销售出库单主表保存报价单 ID，作为整单历史售价来源；不保存报价商品明细 ID。

## 数据模型

### 报价单主表 `quote_sheet`

- 租户、名称、开始日期、结束日期、状态、备注及审计字段。
- 状态为启用或停用，新建默认停用，只有启用的报价单可用于销售。
- 为租户、开始日期、结束日期建立索引，以支持周期重叠校验和按日期查询。

### 报价单明细表 `quote_sheet_detail`

- 报价单 ID、商品 ID、销售单价及审计字段。
- 同一报价单内商品唯一。
- 为报价单 ID、商品 ID 建立唯一索引，用于报价商品查询和数据完整性约束。

### 销售出库明细扩展

- `sale_out_sheet` 新增可空 `quote_sheet_id`。
- 仅当 `sale_out_price_use_unique_price=true` 时由服务端写入；关闭时清空该字段并保持现有商品基础售价逻辑。

## 报价单生命周期

1. 新增、编辑保存前校验必填项、开始日期不晚于结束日期、商品明细非空、商品不重复，以及与其他报价单的周期不重叠。
2. 启用前重复执行周期校验，防止并发或历史数据导致重叠。
3. 停用后该报价单不再参与销售报价查询；已生成销售单保持原价和来源。
4. 删除前检查销售明细是否引用；存在引用时返回业务异常，不执行删除。

## 销售定价流程

### 唯一报价模式开启

1. 根据销售出库单 `orderDate` 查询唯一的已启用报价单。
2. 前端商品搜索和批量选商品仅展示该报价单的商品，并显示报价单价。
3. 创建或修改保存时，后端再次查询报价单，逐条校验所有商品均存在于报价单明细。
4. 服务端使用报价单价覆盖销售明细单价，重新计算税额、金额和单据汇总，并在销售出库单主表写入 `quote_sheet_id`。
5. 销售日期变更时按新日期重新执行上述步骤：商品不存在或没有有效报价单则拒绝保存；商品存在则自动更新为新报价价格。

### 唯一报价模式关闭

- 维持现有逻辑，直接从商品档案的基础销售价取价，不查询或限制报价单，并清空销售出库单主表 `quote_sheet_id`。

## 接口与页面

- 后端在商品模块新增报价单 Controller、Service、Repository、实体、VO、DTO、BO 和 MapStruct Converter，所有读写接口使用 POST。
- 提供分页查询、详情、新增、编辑、删除、启用、停用，以及按销售日期查询可售报价商品接口。
- 前端在商品中心新增“报价单管理”菜单，包含列表页、详情页与新增/编辑页；商品明细采用现有单据式表格，支持检索和批量添加。
- 销售出库新增和修改页加载唯一报价开关后，在开启时按订单日期调用报价商品接口；订单日期变化后刷新候选商品和显示价格。后端始终是最终校验者。

## 错误处理

- 周期重叠：提示与已有报价单的定价周期冲突。
- 无有效报价单：提示该销售日期未找到已启用报价单。
- 商品未报价：提示具体商品未包含在当前报价单中。
- 已引用删除：提示报价单已被销售单使用，不能删除。
- 所有业务规则错误使用 `DefaultClientException`；Controller 仅校验参数并包装为 `InvokeResult`。

## 测试

- 后端单元测试覆盖：周期边界与重叠、启用/停用、重复商品、已引用删除、唯一报价模式创建定价、日期修改自动改价、无报价单和缺商品拦截、关闭唯一报价模式的回退逻辑。
- 前端测试覆盖：日期变化后使用报价商品候选集、报价价带入、唯一报价模式关闭时保持原商品选择逻辑。
