# 销售出库买菜汇总单列化设计

## 背景

`/sale/out` 的“买菜汇总”当前将每个客户生成一列。同一商品在客户较多时，导出表格会横向扩展，不利于查看和打印。需要将客户明细合并为一个固定列，并使用客户昵称作为展示名称。

## 目标

1. 买菜汇总不再为每个客户生成独立列。
2. 每个商品使用固定的“明细数量”列展示所有客户的数量明细。
3. 合并单位和总计列，使用“总重量”展示为“数量单位”，例如 `6公斤`。
4. 客户展示名称优先使用 `Customer.nickName`，昵称为空或仅包含空白字符时使用 `Customer.name`。
5. 保留现有商品分类、商品名称、数量累加和备注去重逻辑。

## 导出格式

固定表头顺序为：

```text
分类 | 商品名称 | 总重量 | 明细数量
```

单个客户的明细格式为：

```text
(客户展示名称)数量/单位
```

有备注时格式为：

```text
(客户展示名称)数量/单位（备注）
```

多个备注使用中文分号连接并去重；多个客户使用 `+` 连接，客户顺序按查询结果中首次出现的顺序。例如：

```text
(绿春56)1.5/公斤（送老张；分两袋）+(平河57)2/公斤（上午送达）
```

总重量使用商品汇总数量和商品单位拼接，例如数量为 `6`、单位为 `公斤` 时输出 `6公斤`；单位为空时仅输出数量。

无数量但存在备注时保留备注文本；无数量且无备注时为空。

## 实现方案

在 `SaleOutSheetServiceImpl.marketBuySummary` 中保留现有明细查询及商品聚合流程，将客户列映射替换为客户展示名称映射，并把每个 `SummaryRow` 的客户单元格序列化为单个“明细数量”字符串；同时将汇总数量和商品单位格式化为“总重量”。客户基础数据继续通过 `customerService.listByIds` 批量加载，避免在汇总循环中逐条查询。

`SummaryRow.cells` 仍以客户 ID 保存中间聚合结果，便于同一客户同一商品累加数量和备注；导出阶段按客户首次出现顺序读取单元格，避免依赖 `HashMap` 顺序。格式化逻辑拆为可测试的包可见静态方法，测试不需要启动 Spring 容器或访问数据库。

空出库单或无明细时仍导出空表，表头使用固定列，不生成客户动态列。

## 测试范围

新增单元测试覆盖：

1. 昵称非空时使用昵称。
2. 昵称为 `null`、空字符串或空白字符串时回退到客户名称。
3. 无备注时只输出客户、数量和单位。
4. 单个备注和多个备注的格式，以及重复备注去重。
5. 多客户明细使用 `+` 合并并保持客户顺序。
6. 总重量按数量和单位拼接，单位为空时不追加单位。

## 非目标

- 不修改前端按钮、请求地址或查询条件。
- 不修改销售出库单、明细导出和按天汇总导出。
- 不改用数据库字符串聚合，避免备注顺序及数据库兼容性问题。
