# 客户结算工作台重构设计

## 目标

将客户结算从“预收款、费用、对账、结算单”四段式流程重构为与供应商结算一致的“结算工作台 + 结算记录”模式。用户可直接针对销售单和销售退货单完成结算，不再创建客户预收款、费用或对账中间单据。

## 范围与边界

- 保留现有客户结算相关数据库表，不删除表、不迁移数据。
- 当前客户预收款、费用、对账、结算业务均无数据，因此可直接移除其前后端实现与接口，不提供旧接口兼容层。
- 保留并重构客户结算单及其明细，使其成为结算结果和结算记录的唯一业务载体。
- 不改动供应商结算现有功能；客户结算仅复用其已验证的流程结构和金额分摊规则。

## 方案选择

采用独立的客户结算工作台实现：在客户结算领域内建立销售业务单据的结算扩展查询、工作台和结算记录页面。该方案与供应商工作台保持交互和金额口径的一致性，同时避免抽象供应商与客户差异所带来的扩大改动风险。

不采用仅合并前端页面的方案，因为其仍依赖旧的中间单据与接口，无法达到清理复杂流程的目标。

## 用户流程

1. 用户进入客户结算工作台，筛选可结算的销售单和销售退货单。
2. 工作台展示客户、单据金额、已收金额、对账金额、已结算金额、未结算金额和结算状态。
3. 用户仅能勾选同一客户的业务单据，输入确认结算金额后直接提交。
4. 系统生成客户结算单与明细，按金额分摊结果更新原始销售业务单据的结算状态。
5. 用户在客户结算记录页查询、查看并导出已生成的结算记录。

## 后端设计

### 工作台查询

新增客户销售业务单据的结算扩展查询能力。查询以销售单和销售退货单为数据源，使用旧客户对账流程已有的业务范围与金额口径，批量聚合每条业务单据的已收、对账、已结算和未结算金额，避免循环查询数据库。

工作台查询和导出接口与供应商结算的收货单扩展查询保持相同职责：控制器只完成参数校验和 `InvokeResult` 响应包装；Service 负责批量聚合和业务编排。

### 直接结算

客户结算创建接口采用工作台提交的单据明细和确认金额，支持直接审核通过。Service 在一个事务内：

1. 校验单据存在、客户一致、状态可结算、金额合法；
2. 以各业务单据当前未结算金额为基数进行金额分摊；
3. 创建客户结算单及明细；
4. 批量更新销售单和销售退货单的结算状态；
5. 写入既有操作日志与时间线。

金额分摊复用供应商结算的规则：确认金额与基数合计的差额平均分摊到每一条明细，金额保留两位小数，最后一条补齐尾差，所有明细合计严格等于确认金额。任一明细为负数时抛出 `DefaultClientException` 并回滚。

如并发操作使业务单据状态在提交期间发生变化，状态更新必须以受影响行数校验，失败时抛出 `DefaultClientException`，事务整体回滚，不生成部分结算记录。

### 结算记录

客户结算记录沿用客户结算单及明细表。提供列表、详情和导出接口，仅呈现最终结算结果，不再关联客户对账、预收款或费用单据。

## 前端设计

- 将客户结算路由收敛为“客户结算工作台”和“客户结算记录”两个入口，页面结构与供应商的 `settle.vue`、`record.vue` 对齐。
- 工作台提供筛选、勾选、确认结算、刷新和导出；确认结算使用新客户结算 API。
- 结算记录页提供列表筛选、详情查看和导出。
- 删除 `frontend/src/views/customer-settle` 下旧的预收款、费用单、对账单和旧结算单页面；删除对应 API 模块、模型和客户结算专用枚举；删除旧路由和菜单引用。

## 删除范围

删除客户预收款、客户费用单、客户对账单和旧客户结算单的 Controller、Service、ServiceImpl、Mapper、Mapper XML、Entity、VO、DTO、BO、Excel 导出类、前端 API/模型、枚举、页面与路由。

数据库表保留，包括客户预收款、费用、对账和旧结算相关表；本次不执行 Flyway 删除迁移。

## 错误处理

- 所有业务校验失败使用 `DefaultClientException`，不抛出 `RuntimeException`。
- Controller 统一返回 `InvokeResult`；需要捕获异常的入口记录错误日志并返回受控失败响应。
- 金额为空、负数、精度异常、跨客户选单、不可结算状态、重复结算和并发状态变化均拒绝提交。

## 测试与验收

- 后端：覆盖销售单、销售退货单及混合勾选的工作台聚合与直接结算；覆盖全额/部分结算、金额分摊、尾差补齐、负数分摊、跨客户、重复结算及并发状态变化。
- 前端：覆盖工作台金额展示、选单限制、提交参数与结算记录展示的关键纯函数或组件行为。
- 清理校验：前端不存在旧客户结算路由、页面或 API 引用；后端不存在旧客户预收款、费用、对账及旧结算接口。
- 构建校验：`cd backend && mvn clean compile -DskipTests`、相关后端测试及 `cd frontend && pnpm run lint` 均通过。
