# 采购收货明细生产日期设计

## 目标

在采购收货单商品明细中增加可选的生产日期字段。字段以字符串保存，用户在前端手动输入；后端仅接受真实日历日期且格式严格为 `yyyy.MM.dd` 的非空值。该字段覆盖采购收货的新增、修改、查询、查看、导入和导出流程。

## 数据与接口

- 在租户库 `tbl_receive_sheet_detail` 新增 `production_date VARCHAR(10) NULL COMMENT '生产日期'`。
- 后端 Java 字段和前端 TypeScript 字段统一命名为 `productionDate`，类型分别为 `String` 和 `string`。
- 在收货明细实体、创建和修改请求、详情及明细查询响应、DTO、MyBatis 映射、Excel 导入与导出模型中贯通该字段。
- 不新增接口；字段作为现有收货单商品明细的一部分传递。
- 既有数据和未填写生产日期的明细保持 `NULL`。

## 页面与数据流

1. 新增和修改收货单的两套页面（关联/不关联采购订单）在商品明细增加“生产日期”普通文本输入列。前端不做格式或日历有效性校验。
2. 创建和修改请求提交 `productionDate` 原始字符串。
3. Service 层在写库前对每条非空生产日期作严格解析：格式必须为 `yyyy.MM.dd`，并且必须是有效日历日期；校验失败抛出 `DefaultClientException`，错误说明对应商品明细。
4. 查询、详情、审核查看及相关商品明细表原样展示已保存的字符串。
5. Excel 导入模板增加“生产日期”列。导入阶段调用同一严格校验，错误提示包含导入行号、字段名和期望格式。
6. 收货单导出及收货明细导出增加“生产日期”列，按存储字符串原样输出。

## 校验与错误处理

- 空值允许，不做默认填充。
- 合法示例：`2026.07.16`、`2024.02.29`。
- 非法示例：`2026-07-16`、`2026.7.16`、`2026.02.30`。
- 不在 Controller 写业务校验；Controller 继续使用现有 `InvokeResult` 响应包装。
- 不调整采购订单、采购退货、库存等非采购收货流程。

## 测试与验证

- 为 Service 校验新增有效日期、格式错误、无效日历日期和空值允许的 JUnit 用例。
- 为导入模型/导入服务验证生产日期能被传入及非法值会返回行级错误。
- 编译后端并运行相关测试；执行前端类型检查或项目现有 lint 命令，确认页面和 TypeScript 模型一致。
