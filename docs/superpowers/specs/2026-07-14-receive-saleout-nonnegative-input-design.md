# 采购收货与销售出库非负数校验设计

## 目标

采购收货单与销售出库单的单价、数量允许为空或 `0`，但在新增、修改和 Excel 导入的所有入口均禁止负数。

## 范围

- 采购收货单：关联采购订单与不关联采购订单的新增、修改页面。
- 销售出库单：关联销售订单与不关联销售订单的新增、修改页面。
- 两类单据的录入页 Excel 导入与查询列表页 Excel 导入。
- 服务端创建、修改接口及导入业务，防止绕过前端校验。

查询列表页现有导入入口不新增任何 UI，仅调整其导入数据校验。

## 方案

### 前端

在八个新增/修改页面的明细行校验与提交前校验中，统一判定单价、数量：

- `null`、空字符串、`undefined` 与 `0` 为合法值。
- 小于 `0` 的数值为非法，提示对应行与字段。
- 保留现有金额汇总与批量填充行为；批量填充值为负数时同样不能写入明细。

### 后端

在采购收货与销售出库的 Service 层提取各自的明细非负数校验，并在创建、修改、录入页导入检查、查询页导入落库前调用。

- 单价字段：采购收货为采购价，销售出库为含税售价；如页面或导入模型还存在成本价，成本价也按相同规则禁止负数。
- 数量字段：采购收货为收货数量，销售出库为出库数量。
- 空值不转换为 `0`，保持现有业务默认值逻辑。
- 负数抛出 `DefaultClientException`；Excel 导入错误包含 Excel 行号及中文字段名。

## 数据流

页面输入或 Excel 文件进入控制器后，由 Service 在持久化之前执行非负数校验。前端校验提供即时反馈，服务端校验作为唯一可信的最终防线；任一明细出现负数时，当前提交或整批查询页导入失败，不产生部分数据。

## 错误处理

- 页面：使用现有 `createError` 显示“第 N 行【字段】不能小于 0”。
- 普通接口：Service 抛出 `DefaultClientException("第 N 行【字段】不能小于0")`。
- Excel：Service 抛出包含 Excel 实际行号（表头后第一行是第 2 行）的 `DefaultClientException`。

## 测试

- 为 Service 明细校验补充 JUnit：空值、`0`、正数通过；单价/数量负数失败；导入失败信息包含行号。
- 前端以现有 lint 与构建验证，确认 Vue 模板和 TypeScript 校验无误。

## 非目标

- 不新增查询列表页导入按钮、页面或路由。
- 不改变单价或数量为空时的金额、库存或默认值业务规则。
- 不调整其他单据类型的校验规则。
